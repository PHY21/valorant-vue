# 邮箱账号部署与验收

## 当前方案

Vue 3 + Supabase Auth。邮箱密码登录，注册验证及忘记密码使用邮件数字验证码。昵称公开给已登录用户，邮箱不在评价中展示。仅登录、注册、验证邮箱、找回与重置页面允许未登录访问。恢复会话期间只能重置密码；修改后全局退出，重新登录。

项目：valorant-atlas，项目 ID `otqseagncvvrhuqfgqqr`，保留原 PHP 项目。旧版用户名账号记录保留，但不满足新版真实邮箱会员资格。原 PHP 账号不迁移。

## 后端部署

1. 按版本顺序应用三份迁移，最后为 `20261106143314_email_membership.sql`。它替换旧用户名限制，保留旧账号，收紧昵称和评价 RLS，并建立 `atlas_catalog`。
2. 以管理权限将 `supabase/catalog.seed.json` 导入 `atlas_catalog` 的 id=1、content 字段。此文件是公开课程样本，不是私密数据；从 Pages 构建资源移除，运行时必须验证账号后才能通过 API 读取。公开仓库历史仍包含样本。
3. Supabase Email provider 开启 Confirm email；禁用匿名登录；密码最少 8 位。OTP 推荐 10 分钟有效期，保留服务端发送和验证频率限制。
4. 自定义 SMTP 使用用户选择的邮箱。SMTP 授权码只由用户在 Supabase 后台输入，不进入仓库或客户端。
5. Confirm sign up 与 Reset password 邮件模板使用 `{{ .Token }}`，引导回网站的验证/重置页输入验证码。不依赖 URL token fragment，兼容 GitHub Pages hash 路由和跨设备输入。
6. 前端只使用 `.env.local` / GitHub Actions variables 中的 URL 和 publishable key，禁止 secret/service_role key。

## 访问控制与边界

路由守卫等待会话恢复；退出清空图鉴，忽略迟到的加载响应。后端私有资格函数依据 auth.users 中的真实邮箱和 email_confirmed_at，拒绝旧内部账号、未验证邮箱及匿名账号；不信任用户可改的 metadata 权限。会员可读图鉴与评价，只能新增或删除本人评价，不能更改数据图鉴、伪造作者或时间。

收藏和旧评价仍在当前浏览器。用户数据不通过种子导出。SMTP 个人邮箱适合当前小规模演示，投递效果和服务商限制须实际验证。全局退出撤销刷新会话；已发出的短期 access token 按 Supabase 默认到期行为处理。
