# 在线账号部署与验收

## 架构

用户选择用户名＋密码的真实在线账号，不收集邮箱，暂不提供密码找回。用户名 3–24 位、字母开头、仅字母数字下划线、不区分大小写；昵称可用中文。Supabase 内部使用 `atlas.<用户名>@accounts.invalid` 标识，`.invalid` 不用于发邮件。密码哈希、验证与会话由 Supabase Auth 管理，业务代码不保存密码。

项目：valorant-atlas；项目 ID：`otqseagncvvrhuqfgqqr`；新加坡免费项目，独立于原 PHP/MySQL 作业。

## 服务设置

1. 按顺序执行 `supabase/migrations/202611060001_accounts.sql` 与 `202611060002_username_accounts.sql`。后一迁移在数据库层拒绝真实邮箱、错误标识和用户名变更；必须先部署，再开放用户名注册。
2. 此专用项目开启 Email provider 作为内部用户名密码认证通道，关闭 Confirm email，最小密码长度 8。不启用社交登录、匿名登录或邮件发送。用户明确选择不验证/收集邮箱，不应对其他真实邮箱项目套用此设置。
3. Site URL 为 `https://phy21.github.io/valorant-vue/`。认证不接收 URL token fragment，无邮箱回调。
4. 使用项目 URL 与公开 publishable key，写入 `.env.local` 和 GitHub Actions Repository variables：`VITE_SUPABASE_URL`、`VITE_SUPABASE_PUBLISHABLE_KEY`。不使用 secret/service_role key。Pages 在配置缺失或无效时阻止部署。

## 验收

- `npm test`、`npm run build`。PGlite 测试执行真实迁移，模拟托管角色：访客不能写、B 不能冒名 A 或删 A 评论、A 可删自己评论、不可伪造时间或改昵称；内部账号标识触发器拒绝真实邮箱及篡改用户名。此测试不替代真实托管服务验收。
- 真实注册两个专用测试账号，验证重复用户名、错误密码、刷新恢复登录、独立会话登录、退出。
- A 发表、B 读取但不可删除或冒名；匿名不可写。通过直接 REST 请求检查服务器权限，而非只看按钮。
- 测试评价已由作者删除。3 个专用测试账号作为验收记录保留，不属于真实访客；凭据不进入仓库。
- 验证移动端及 Pages 深链接后推 main，等待 Actions 成功，再验收线上功能。

## 功能边界

收藏仍仅在当前浏览器保存。升级前评价仍是本地私有历史，不自动公开或绑定账号。新评价公开，昵称不保证唯一，权限以 UUID 为准。原 PHP 账号不会迁移。注册/登录后回到原页面。账号注册不验证现实身份；没有邮箱、密码找回、改密码、改用户名或自行删账号入口。
