# 在线账号部署与验收

## 当前状态

账号与评论代码位于 `feature/online-accounts`。本地测试通过不等于真实服务上线。尚待连接 Supabase、配置认证邮件、执行迁移并验收后，再合并 main 部署。

## 服务设置

1. 使用独立 Atlas Supabase 项目，不改动原 PHP/MySQL 数据库。
2. 以数据库管理员身份执行 `supabase/migrations/202611060001_accounts.sql` 一次。昵称只允许服务器创建；公开评论以 `auth.uid()` 校验作者。旧本地评价不会自动迁移。
3. 启用邮箱密码认证、开启 Confirm email、服务器最小密码长度 8。Site URL 为 `https://phy21.github.io/valorant-vue/`；Redirect URLs 添加该精确地址，开发阶段另加 `http://127.0.0.1:5173/`。
4. 配置发件服务及 SMTP。Supabase 默认邮件服务只给项目组织成员发信，不能拿来验收普通访客注册。保持邮箱确认开启。参考 [Supabase SMTP 文档](https://supabase.com/docs/guides/auth/auth-smtp)。
5. 从 Connect / API Keys 获取项目 URL 与 **publishable** key，填入 `.env.local`（参考 `.env.example`），并在 GitHub Actions Repository variables 中配置同名 `VITE_SUPABASE_URL`、`VITE_SUPABASE_PUBLISHABLE_KEY`。前端不接收 legacy JWT key、secret key 或 service_role key。
6. 认证回调使用 SDK 的 implicit flow，在 Vue Hash Router 创建前处理 token fragment，再清理地址。参考 [Supabase implicit flow](https://supabase.com/docs/guides/auth/sessions/implicit-flow)。浏览器保存的是 SDK 会话，不保存密码；本应用没有自建密码数据库。

## 发布前验收

- `npm test`、`npm run build`。测试包含内存 PostgreSQL (PGlite) 上执行实际 SQL 迁移，模拟 Supabase 的角色与 auth.uid 接口：访客不能写、B 不能冒名 A 或删 A 的评论、A 可删自己的评论、不能改写时间或昵称。它不替代托管服务验收。
- 用两个测试邮箱完成真实注册和邮件验证；重复邮箱返回通用提示；错误密码、未验证邮箱、过期链接均有提示。
- 在第二浏览器/设备登录同一账号，刷新恢复会话；退出后不能发表。旧 PHP 账号不会自动存在于新服务。
- A 发表后 B 能看但不能删除；用 B 的 token 直接请求删除 A 评论仍不成功；匿名写入失败。
- 测试 SDK 网络错误和邮件重发限流。测试完成后清理专用测试记录。
- 检查移动端、GitHub Pages 深链接、构建产物不含服务端密钥，再推 main；等 Actions 成功并检查线上页面。

## 范围

收藏仍为当前浏览器本地保存。升级前的评价仍在详情页折叠区，私有且不绑定账号。新评价公开可见，昵称不保证唯一，权限以用户 UUID 为准。本次不包含改密码、找回密码或账号删除页面。

首次注册的确认邮件打开后进入账号页；已有账号登录可返回原详情页。首次注册确认后的返回原详情页优化暂缓。
