# 从 PHP 作业到 Vue 3 在线作品

先写下一条能在浏览器里走完的验收路径。例如「会员收藏一支队 → 管理员发布赛果 → 会员收到提醒并点回比赛」。按本次需求裁剪；只做公开图鉴时，用「搜索 → 筛选 → 详情 → 刷新」就够。若用户只要诊断、讲解或本地修改，交付到那个范围。

## 执行步骤与判断标准

1. **确定哪一份是原作。** 查看工作目录、Git 根目录、远端、未提交文件、PHP 入口、SQL 和素材目录。辨清运行副本和提交副本。原版要保留时，在单独的升级目录或仓库开发；遇到多个同名文件，用内容、调用关系和 Git 状态确认归属。**验收**：能指出原版启动入口、新版工作目录、要发布的目标；私人截图、环境文件和临时测试脚本不混入提交。
2. **用一小批数据先走通页面。** 为一个实体写清主键、外键、列表和详情所需字段。把可展示的数据从 SQL 导出成种子，保留稳定 ID，并核对记录数、空值、找不到的外键及素材路径。若同一个字段随时间变化，明确页面展示「现在」还是「当时」。**验收**：选一名转过队的选手，详情能显示当前队伍，筛选历史赛事后能从那届成绩查到当届队伍。一般图鉴可换成产品现价与历史订单价等同类案例。
3. **迁移一条完整的用户操作。** 用 Vue 3 组件实现列表和详情，用路由表达筛选条件或详情 ID，确有跨页共享状态时再使用 Pinia。开发时通过 Vite 服务访问，部署前用实际项目子路径预览构建结果。**验收**：从首页能走到详情，刷新和浏览器后退正常；没有结果、加载失败、图片或视频不可用时，用户知道接下来怎么做。
4. **根据需求选后端。** 静态托管承担前端文件；PHP 逻辑、真实账号和跨设备数据需要服务端。可以保留已有 API，也可迁移到 Supabase。需要会员访问时，数据库或 API 必须验证身份；已发布到静态资源或公开源码里的内容仍可被读取。长期有效的写入密钥和 SMTP 凭据只放服务端。**验收**：未登录、普通会员、管理员分别直接调用受限接口，得到与其权限一致的结果；要求邮件验证或找回密码时，用可收信的测试邮箱走完流程。
5. **有外部同步或后台发布时，把人工审核做成可见的操作。** 识别资料页与搜索页，按稳定来源编号区分同名对象，逐字段展示本站值、来源值和勾选后的结果。用户确认时校验原值或修订号，写入和日志一起提交。**验收**：仅绑定来源时能说清是哪项后台设置；取消预览无写入；重复发布和两位管理员同时修改都不会多记或覆盖新结果。涉及收藏消息和更正时，按[故障与复验手册](references/failures.md)检查收件人。
6. **分别验证代码、部署和线上行为。** 查项目现有脚本和锁文件，运行依赖安装、相关测试、构建和本地预览。本例用 `npm ci`、`npm test`、`npm run build`、`npm run preview`。获准上线时，只提交本次文件，确认远端分支指向本地提交，再等待对应的托管部署。**验收**：访问正式地址，刷新一条深链接，点过本次需求的关键操作；用隔离测试数据验证有副作用的路径。说明哪些检查用了真实服务、哪些使用了模拟账号，哪些还缺少证据。

## 发布核验工具

对使用 Vite 本地模块入口、部署在 GitHub Pages 子路径的项目，可从 Skill 目录运行：

```text
python scripts/verify_pages.py --dist "/path/to/project/dist" --url "https://OWNER.github.io/REPO/"
```

先用与发布流程相同的公开配置和 base 构建。工具对比两个入口 HTML 引用的模块路径，并逐个校验线上模块内容与本地文件的 SHA-256。退出码 0 表示这些入口一致；深链接、登录、图片、懒加载页面和数据库操作仍需从浏览器验收。若失败，先看错误发生在构建、入口路径还是资源内容，再决定是否重新发布。

遇到具体症状，查[故障与复验手册](references/failures.md)。交付时附源码位置、演示入口和一条可重复的验收路径。如果用于课程答辩，区分小组原作和个人后续升级，按实际分工介绍。
