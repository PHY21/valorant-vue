# 出现问题时怎么查

下面的复现来自 VALORANT Atlas 的开发场景。原因栏给出应验证的解释；同一症状在新项目里可能有别的原因。先用一条最小用例确认，再验证修复。

| 现象或容易踩的坑 | 失败原因或判断依据 | 下次怎么处理、怎样算修好 |
| --- | --- | --- |
| 双击源码目录的 `index.html`，页面空白 | 这个文件是 Vite 源码入口，会引用模块和 Vue 单文件组件；`file://` 缺少开发服务器的转换和路由环境 | 检查 `package.json` 中已有脚本。通过开发服务器访问；交付前再走一次生产构建的 HTTP 预览。 |
| 本地正常，Pages 上刷新详情、加载头像或视频失败 | 检查失败请求的完整 URL、HTTP 状态、内容类型。项目挂在子路径时，写死的根路径会指向域名根目录；静态托管也可能没有路由回退 | 让 Vite base 与发布目录一致，按 base 生成素材地址；根据托管能力选 hash 路由或配置回退。访问线上深链接，播放并拖动一段实际视频。 |
| 视频卡片能显示，点击后无法观看 | 缩略图成功只能证明图片可读。播放器可能被来源站限制嵌入，也可能遇到媒体 URL 失效或编码不支持 | 分别检查媒体响应、浏览器解码和嵌入限制。选可用且允许使用的素材；若有可分发版本，可托管兼容格式并保留来源链接。用目标浏览器实播，覆盖报告失败的那个按钮。 |
| 注册或找回接口返回成功，用户却收不到信 | 请求受理并不能证明邮件投递成功；检查发送限制、SMTP 发件配置、身份提供商日志及垃圾邮件 | 先测试一个符合实际访客条件的收件地址，跟到收信、验证或重置、重新登录。密码和临时码由用户在相应页面填写。 |
| 同步 Smoggy 失败，或有可能更新错人 | 用户贴的是搜索页，原解析器只收资料页；同一搜索词确实可能返回多个同名选手 | 支持的来源域名与路径在服务端校验。把搜索结果列成含编号的候选项，选定后读取详情。核验绑定编号；遇到多队、无队或无法匹配时给出待核对状态。用用户原链接复验，预览不触发发布。 |
| 页面写着「1 项差异」，管理员不知道读者会看到什么 | 初次保存来源链接也被算作选手变更；总数无法表达姓名、战队和后台来源的区别 | 分列公开资料和后台来源，勾选字段时同步显示发布后的资料。用「只差链接」「队伍改变」「取消勾选」三种状态走一遍，核对提交字段与预览相符。 |
| 查询某届比赛时显示了选手后来的战队 | 统计已按赛事筛选，队名却从当前选手表读取。课程数据中的例子是 Klaus：雷克雅未克 2021 的参赛队为 KRU，而当前资料记录 VL | 按当届成绩的队伍 ID 查队名；总榜标清当前战队，缺失历史值时显示未收录。切换赛事和统计指标，比较队名、排序与分数。 |
| 收藏换设备消失，或离线期间没有消息 | 浏览器收藏没有账号归属；实时订阅本身也不保存离线事件 | 将关注关系按账号持久化，旧浏览器收藏由本人选择导入。发布时保存收件记录，再用实时事件更新红点；重连时从服务端补读。测试关注双方只收一条、用户之间互不可读、刷新后已读状态一致。 |
| 比分填反后重新录入，导致交手次数变多 | 把更正当成第二场比赛，或按当前关注名单发送历史更正 | 用原比赛 ID 原位修改，校验修订号，记录旧值、新值和原因。模拟 2:1 改为 1:2，应仍只有一场，胜方翻转；原收件人即使取消收藏也收到更正，后来才关注的人不收到旧提醒。 |
| GitHub 已有新提交，演示地址看起来仍是旧版 | 代码推送、Actions 构建、Pages 部署、浏览器读到资源是不同环节 | 先核对远端提交和该提交的部署结果，再比对线上入口模块。若本地与 CI 配置不同先重建；若流程报错处理首条有效错误。功能异常再检查具体页面、API 和权限，不盲目重复推送。 |

## 验收证据怎么用

- 测试服务端权限时直接请求接口。只确认按钮隐藏，不能说明数据受保护。
- 测试修改、删评、授权、转会或赛果通知时，优先在隔离环境使用测试记录。预览、模拟写入、真实持久化是三种不同结果，验收记录写明是哪一种。
- 外部来源暂不可用时保留原数据，并显示可重试或手动核对的入口。登录授权、SMTP 密码或来源站访问受阻时，说明具体阻点与用户能完成的最小一步；不要因一次失败而削弱鉴权。
